# M4 — Implement both runner adapters

[Roadmap](README.md) · **Depends on:** [M2](m2-storage-and-exports.md),
[M3](m3-processes-and-git.md) · **Enables:** [M5](m5-planning-and-scheduling.md)

## Deliverable

A runner-neutral interface with working Codex and OpenCode implementations, exact
route validation, structured-output validation, diagnostics, and lifecycle
ownership. Fix the shared contract before working independently on the adapters.

Preserve the Rust snapshot’s declared protocol baselines:

| Client | Pinned reference version |
| --- | --- |
| Codex | `0.153.4` |
| OpenCode | `1.18.30` |

These are reference versions, not claims about the latest releases. Do not
upgrade an integration merely because a newer client exists. Validate Codex
messages against schemas generated by the pinned CLI, and OpenCode against its
pinned server contract and existing fixtures.

## Acceptance criteria

1. Codex initialization, model/account discovery, thread start/resume, turn start,
   event correlation, and interruption pass.
2. OpenCode startup, loopback authentication, HTTP/SSE handling, session
   creation/resumption, model/provider/variant checks, and structured completion
   pass.
3. Preserve per-invocation ownership and task-local lazy backend startup.
   OpenCode-only operation does not require Codex.
4. Workspace, session, model, effort/variant, and permission mismatches fail
   visibly. Mixed-backend routing preserves exact selected identities.
5. Tests cover fragmented messages, interleaved unrelated events, missing
   completion, duplicate or stale events, disconnects, interactive requests,
   and cancellation.
6. Preserve the runner protocol’s 16,000,000-byte bound. Do not substitute a smaller
   default scanner limit, the process capture limit, or an unbounded buffer.
7. Preserve OpenCode’s temporary worker policy, disabled project overrides,
   redirect policy, and helper-process restrictions.
8. Both pinned real-client/synthetic-provider contract suites pass without live
   credentials or paid provider calls.

## Verification and evidence

Port `tests/runners.rs` and `tests/contracts.rs`. Reuse
`tests/fixtures/codex.py`, `tests/fixtures/opencode.py`, and
`tests/fixtures/provider.py`, and run applicable shared executable scenarios.

Record actual client versions, schema provenance, commands, and results. A
fixture-only pass is not a real-client contract pass. Unavailable pinned binaries
leave the corresponding required gate unrun and block milestone completion.
